# Constrained EIP-712 ERC-2612 Permit

[EVM index](evm.md) · [API index](../API.md)

Route: `POST v1/evm/eip712/sign`

Request type: `EVMEIP712SignRequest`

Supported contract:

- schema ID: `eip2612-permit-v1`
- schema version: `1`
- primary type: `Permit`
- fixed domain: `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)`
- fixed message: `Permit(address owner,address spender,uint256 value,uint256 nonce,uint256 deadline)`
- signature encoding: `rsv-v27`, 65 bytes `r || s || v` with low-S and `v` equal to 27 or 28

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `key_id` | string | yes | Custody key. |
| `chain_family` | string | yes | Must be `evm`. |
| `network` | string | yes | Must be explicitly allowed by policy. |
| `request_id` | string | yes | Non-empty correlation identifier. |
| `expected_signer_address` | string | yes | Must match the stored key and `message.owner`. |
| `chain_id` | decimal string | yes | Positive uint256; must equal `domain.chain_id` and be allowed by policy. |
| `schema_id` | string | yes | Must be `eip2612-permit-v1` and be policy-allowed. |
| `schema_version` | string | yes | Must be `1`. |
| `domain.name` | string | yes | Non-empty token domain name. |
| `domain.version` | string | yes | Non-empty token domain version. |
| `domain.chain_id` | decimal string | yes | Must equal top-level `chain_id`. |
| `domain.verifying_contract` | address | yes | Non-zero token contract; must be in `allowed_token_contracts`. |
| `message.owner` | address | yes | Non-zero permit owner and selected key signer. |
| `message.spender` | address | yes | Must be in `allowed_contract_destinations`. |
| `message.value` | decimal string | yes | uint256, capped by `max_value` when configured. |
| `message.nonce` | decimal string | yes | uint256 supplied by the caller. |
| `message.deadline` | decimal string | yes | uint256 supplied by the caller. |

Example request:

```json
{
  "key_id": "payments-evm",
  "chain_family": "evm",
  "network": "ethereum-sepolia",
  "request_id": "permit-001",
  "expected_signer_address": "0x1111111111111111111111111111111111111111",
  "chain_id": "11155111",
  "schema_id": "eip2612-permit-v1",
  "schema_version": "1",
  "domain": {
    "name": "Example Permit Token",
    "version": "1",
    "chain_id": "11155111",
    "verifying_contract": "0x2222222222222222222222222222222222222222"
  },
  "message": {
    "owner": "0x1111111111111111111111111111111111111111",
    "spender": "0x3333333333333333333333333333333333333333",
    "value": "1000000",
    "nonce": "7",
    "deadline": "2000000000"
  }
}
```

Response type: `EVMEIP712SignResponse`

```json
{
  "data": {
    "api_version": "v1",
    "key_id": "payments-evm",
    "chain_family": "evm",
    "network": "ethereum-sepolia",
    "operation": "evm_eip712_typed",
    "signer_address": "0x1111111111111111111111111111111111111111",
    "request_id": "permit-001",
    "schema_id": "eip2612-permit-v1",
    "schema_version": "1",
    "domain_separator": "0x...",
    "struct_hash": "0x...",
    "eip712_digest": "0x...",
    "signature": "0x...",
    "signature_encoding": "rsv-v27",
    "r": "0x...",
    "s": "0x...",
    "v": 27
  }
}
```

The service constructs the domain separator, struct hash, and final `0x1901` digest internally, signs it through custody, and recovers the owner before returning. Other primary types, extra domain fields such as `salt`, and caller-provided type definitions are rejected.


## `POST v1/evm/eip712/verify`

Request type: `EVMEIP712VerifyRequest`. Supply the same `chain_family`, `network`, `request_id`, signer, chain, schema, domain, and message fields used for signing, plus the 65-byte `signature`. No `key_id` is required.

```json
{
  "chain_family": "evm",
  "network": "ethereum-sepolia",
  "request_id": "permit-verify-001",
  "expected_signer_address": "0x1111111111111111111111111111111111111111",
  "chain_id": "11155111",
  "schema_id": "eip2612-permit-v1",
  "schema_version": "1",
  "domain": {
    "name": "Example Permit Token",
    "version": "1",
    "chain_id": "11155111",
    "verifying_contract": "0x2222222222222222222222222222222222222222"
  },
  "message": {
    "owner": "0x1111111111111111111111111111111111111111",
    "spender": "0x3333333333333333333333333333333333333333",
    "value": "1000000",
    "nonce": "7",
    "deadline": "2000000000"
  },
  "signature": "0x..."
}
```

Response type: `EVMEIP712VerifyResponse`. It returns `schema_id`, `schema_version`, the reconstructed `digest`, `recovered_signer`, `signature_valid`, and common inspection fields.

```json
{
  "data": {
    "api_version": "v1",
    "chain_family": "evm",
    "network": "ethereum-sepolia",
    "operation": "evm_eip712_typed",
    "schema_id": "eip2612-permit-v1",
    "schema_version": "1",
    "digest": "0x...",
    "recovered_signer": "0x1111111111111111111111111111111111111111",
    "signature_valid": true,
    "request_id": "permit-verify-001"
  }
}
```
