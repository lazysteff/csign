# ERC-4337 v0.9 SimpleAccount UserOperation

[EVM index](evm.md) · [API index](../API.md)

Route: `POST v1/evm/erc4337/user-operations/sign`

Request type: `EVMUserOperationSignRequest`

Supported contract:

- protocol: `erc4337-v0.9`, pinned to account-abstraction v0.9.0 behavior
- account implementation: `simple-account`
- account implementation version: `0.9`
- signing schema: `simple-account-eip712-v1`
- signature encoding: `rsv-v27`
- canonical v0.9 EntryPoint deployment: `0x433709009b8330fda32311df1c2afa402ed8d009`

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `key_id`, `chain_family`, `network`, `request_id` | string | yes | Advanced signing base fields. |
| `expected_signer_address` | address | yes | SimpleAccount owner; must match the selected key. It is not the smart-account `sender`. |
| `chain_id` | decimal string | yes | Positive uint256 and policy-allowed. |
| `entry_point` | address | yes | Caller-selected EntryPoint; must be in `allowed_entry_points`. |
| `protocol_version` | string | yes | `erc4337-v0.9` and policy-allowed. |
| `account_implementation` | string | yes | `simple-account` and policy-allowed. |
| `account_implementation_version` | string | yes | `0.9`. |
| `account_signing_schema` | string | yes | `simple-account-eip712-v1` and policy-allowed. |
| `expected_user_operation_hash` | 32-byte hex | no | Consistency check against the internally reconstructed hash. |
| `user_operation.sender` | address | yes | Smart-account address. |
| `user_operation.nonce` | decimal string | yes | uint256. |
| `user_operation.call_data` | hex bytes | yes | Complete account calldata. When `allowed_selectors` is configured, this must contain at least a 4-byte selector and that selector must be allowed. |
| `user_operation.call_gas_limit` | decimal string | yes | uint128. |
| `user_operation.verification_gas_limit` | decimal string | yes | uint128. |
| `user_operation.pre_verification_gas` | decimal string | yes | uint256. |
| `user_operation.max_fee_per_gas` | decimal string | yes | uint128. |
| `user_operation.max_priority_fee_per_gas` | decimal string | yes | uint128 and no greater than `max_fee_per_gas`. |
| `user_operation.factory` | `ERC4337Factory` | no | `address` plus `data`. Mutually exclusive with `eip7702`. |
| `user_operation.eip7702` | `ERC4337EIP7702Context` | no | `delegate_address` plus `data`. Mutually exclusive with `factory`; delegate must be policy-allowed. |
| `user_operation.paymaster` | `ERC4337Paymaster` | no | Address, verification/post-op gas, data, and optional externally produced Paymaster signature. |

`ERC4337Factory` contains `address` and `data`. `ERC4337EIP7702Context` contains `delegate_address` and `data`. `ERC4337Paymaster` contains `address`, `verification_gas_limit`, `post_op_gas_limit`, `data`, and optional `signature`; both Paymaster gas limits are canonical uint128 decimal strings.

  "protocol_version": "erc4337-v0.9",
  "account_implementation": "simple-account",

  "account_signing_schema": "simple-account-eip712-v1",
  "user_operation": {
    "sender": "0x4444444444444444444444444444444444444444",
    "nonce": "0",
    "call_data": "0x",
    "call_gas_limit": "100000",

```json

  "data": {
    "api_version": "v1",
    "key_id": "payments-evm",
    "chain_family": "evm",
    "network": "ethereum-sepolia",
    "operation": "evm_erc4337_user_operation",
    "signer_address": "0x1111111111111111111111111111111111111111",
    "request_id": "userop-001",
    "protocol_version": "erc4337-v0.9",
    "account_implementation": "simple-account",
    "account_implementation_version": "0.9",
    "account_signing_schema": "simple-account-eip712-v1",
    "user_operation_hash": "0x...",
    "account_signing_digest": "0x...",

    "signature_encoding": "rsv-v27"
  }

```

The UserOperation signature field itself is not accepted as input. CSign constructs the v0.9 packed representation and EIP-712 UserOperation hash. An optional Paymaster signature is transported in the v0.9 Paymaster suffix and excluded from the wallet hash according to that protocol; CSign does not create or validate Paymaster business authorization.


## `POST v1/evm/erc4337/user-operations/verify`

Request type: `EVMUserOperationVerifyRequest`. Supply the complete structured v0.9 UserOperation and all protocol/account identifiers from the signing request, plus the 65-byte `signature`. There is no `key_id` or `expected_user_operation_hash` field.

```json
{
  "chain_family": "evm",
  "network": "ethereum-sepolia",
  "request_id": "userop-verify-001",
  "expected_signer_address": "0x1111111111111111111111111111111111111111",
  "chain_id": "11155111",
  "entry_point": "0x433709009b8330fda32311df1c2afa402ed8d009",
  "protocol_version": "erc4337-v0.9",
  "account_implementation": "simple-account",
  "account_implementation_version": "0.9",
  "account_signing_schema": "simple-account-eip712-v1",
  "user_operation": {
    "sender": "0x4444444444444444444444444444444444444444",
    "nonce": "0",
    "call_data": "0x",
    "call_gas_limit": "100000",
    "verification_gas_limit": "150000",
    "pre_verification_gas": "50000",
    "max_fee_per_gas": "2000000000",
    "max_priority_fee_per_gas": "1000000000"
  },
  "signature": "0x..."
}
```

Response type: `EVMUserOperationVerifyResponse`. It returns `protocol_version`, `account_implementation`, `user_operation_hash`, `account_signing_digest`, `recovered_signer`, and `signature_valid`.

```json
{
  "data": {
    "api_version": "v1",
    "chain_family": "evm",
    "network": "ethereum-sepolia",
    "operation": "evm_erc4337_user_operation",
    "protocol_version": "erc4337-v0.9",
    "account_implementation": "simple-account",
    "user_operation_hash": "0x...",
    "account_signing_digest": "0x...",
    "recovered_signer": "0x1111111111111111111111111111111111111111",
    "signature_valid": true,
    "request_id": "userop-verify-001"
  }
}
```
